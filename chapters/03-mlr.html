Multiple Linear Regression — Exam Kit

Simple notes built from the faculty notebook: predict House PRICE from many features, check every assumption, drop weak features, and evaluate the model. Ends with a full solve of the Model QP.

1

Big Picture & Data

Multiple Linear Regression (MLR) predicts one numeric target using many input variables.

PRICE = b0 + b1·X1 + b2·X2 + … + bk·Xk
  • Goal: predict house PRICE from area characteristics.
  • Simple LR (Session 2) = 1 input. MLR (Session 3) = 2 or more inputs.
Key features: CRIM (crime rate), RM (avg rooms), AGE, DIS (distance to work centres), TAX, PTRATIO (pupil-teacher ratio), LSTAT (% lower-status), CHAS (river Y/N — the categorical one), and PRICE = target.

Outlier Analysis & Treatment

Outliers = extreme values that pull the regression line and break assumptions.

Step 1 — See them (boxplots)

df_housing.boxplot()                       # all variables
df_housing.drop(['TAX','B'],axis=1).boxplot()   # drop big-scale cols for a clearer view
df_housing[['NOX','RM','DIS']].boxplot()   # zoom into similar-range cols

Why drop TAX & B first? Their values are huge, so they flatten every other box. Removing them makes the smaller variables readable.

Step 2 — Remove them (IQR method)

numeric_df = df_housing.select_dtypes(include=np.number)
Q1 = numeric_df.quantile(0.25)
Q3 = numeric_df.quantile(0.75)
IQR = Q3 - Q1

lower = Q1 - 1.5*IQR
upper = Q3 + 1.5*IQR

outliers = ((numeric_df < lower) | (numeric_df > upper)).any(axis=1)
df_housing_clean = df_housing.loc[~outliers].copy()
  • IQR = Q3 − Q1 (middle 50% spread).
  • Any point below Q1 − 1.5·IQR or above Q3 + 1.5·IQR = outlier.
  • ~outliers keeps only the clean rows.

Scaling & add_constant

# split into features (X) and target (y)
df_feature = df_housing_clean.drop('PRICE', axis=1)
df_target  = df_housing_clean['PRICE']

# scale ONLY the numeric features
numeric_cols = df_feature.select_dtypes(include='number').columns
scaler = StandardScaler()
df_feature[numeric_cols] = scaler.fit_transform(df_feature[numeric_cols])

# statsmodels needs an intercept column
df_feature = sm.add_constant(df_feature)
  • StandardScaler → each numeric feature becomes mean 0, std 1. Puts all features on the same footing so coefficients are comparable.
  • Only numeric columns are scaled (not the categorical CHAS).
  • add_constant() → adds a column of 1s so the model can learn the intercept b0.
Exam: statsmodels OLS does not add the intercept for you — you must sm.add_constant().
7

Assumptions to Check BEFORE Building

Two assumptions are checked before the model:

7.1 Dependent variable must be numeric

df_target.dtype   # must be int/float → satisfied
Why: regression predicts numbers. If the target were categories (0/1 disease), it would be a classification problem, not regression.

7.2 No (or little) Multicollinearity

Multicollinearity = input variables are highly correlated with each other. It makes coefficients unstable and unreliable.

a) Correlation heatmap

sns.heatmap(df_feature.corr(numeric_only=True), annot=True, vmin=-1, vmax=1)
# show only strong pairs (>0.6 or <-0.6)
sns.heatmap(df_feature.corr()[np.abs(df_feature.corr()) > 0.6], annot=True)

Values near +1 / −1 = strong correlation. But the heatmap alone is not enough → use VIF.

b) Variance Inflation Factor (VIF)

VIF = 1 / (1 − R²)
vif = pd.DataFrame()
vif["VIF_Factor"] = [variance_inflation_factor(df_num.values, i)
                     for i in range(df_num.shape[1])]
vif["Features"] = df_num.columns
vif.sort_values('VIF_Factor', ascending=False)

# highest VIF was RAD → drop it, then recompute
df_num = df_num.drop('RAD', axis=1)
VIF valueMeaning
VIF = 1No correlation
1 < VIF < 5Moderate — usually OK
VIF > 5High — drop / fix the variable
What the notebook did: RAD had the highest VIF → dropped it → recomputed VIF → multicollinearity resolved.
8

Categorical → Dummy Variables

Regression needs numbers, so the categorical column (CHAS = river Y/N) is converted using dummy encoding.

df_feature = pd.get_dummies(data=df_feature, drop_first=True, dtype=np.uint)
  • Dummy variable = a 0/1 column for a category.
  • A variable with N categories needs N − 1 dummies (drop_first=True).
  • Dropping one avoids the dummy trap (a new multicollinearity).

Worked example — 3 categories → 2 dummies

Manufacturer takes 3 values (Ford, Honda, Tata) → make 3 − 1 = 2 dummies. Ford is the dropped base category.

ValueMfr_HondaMfr_Tata
Ford (base)00
Honda10
Tata01
Premium = b0 + b1·Mileage + b2·Mfr_Honda + b3·Mfr_Tata

How the dummy changes the intercept (slope b1 stays the same, only the start point shifts):

CategoryEquation becomesIntercept
Fordb0 + b1·Mileageb0 (base)
Honda(b0 + b2) + b1·Mileageb0 + b2
Tata(b0 + b3) + b1·Mileageb0 + b3
Read it as: b2 = how much Honda's price differs from Ford; b3 = how much Tata differs from Ford. Each dummy just moves the line up or down.

Build the MLR Model

MLR_full_model = sm.OLS(df_target, df_feature).fit()
print(MLR_full_model.summary())

The summary gives everything: coefficients, p-values, R², Adjusted R², F-statistic, Durbin-Watson.

Score card (compare models)

score_card = pd.DataFrame(columns=['Model_Name','R-squared','Adj.R-sqr','MSE'])

y_pred = MLR_full_model.fittedvalues
score_card.loc[len(score_card)] = ['Full Model',
    MLR_full_model.rsquared, MLR_full_model.rsquared_adj,
    mean_squared_error(df_target, y_pred)]
Why a score card? Every time we change the model (drop a feature, add interaction), we add one row → easy to see which model is best.

Assumptions to Check AFTER Building

Four assumptions are checked on the residuals (residual = actual − predicted) after the model is built.

10.1 Linear Relationship

plt.scatter(MLR_vif_model.fittedvalues, MLR_vif_model.resid)
plt.axhline(0)
  • Plot residuals vs fitted values (and vs each predictor).
  • Good: points scattered randomly around 0, no pattern → relationship is linear.

10.2 No Autocorrelation Durbin-Watson

  • Autocorrelation = residuals are correlated with each other (a pattern over order).
  • Read the Durbin-Watson value from model.summary().
DW valueMeaning
0 – 2Positive autocorrelation
≈ 2No autocorrelation (good)
2 – 4Negative autocorrelation
Notebook result: DW ≈ 1.88 (near 2) → assumption satisfied.

10.3 Homoscedasticity Breusch-Pagan

Residuals should have constant variance (homoscedastic). Non-constant variance = heteroscedasticity (funnel shape in the plot).

bp = sms.het_breuschpagan(MLR_vif_model.resid, df_feature_vif)
print('Test stat:', bp[2])
print('P value:',   bp[3])
  • H₀: errors are homoscedastic (constant variance).
  • If p > 0.05 → keep H₀ → homoscedastic ✅.
  • If p < 0.05 → heteroscedastic ❌.

Goldfeld-Quandt test alternative

Another test for the same homoscedasticity assumption.

  • H₀: errors are homoscedastic (equal variance).
  • H₁: errors are heteroscedastic (unequal variance).
  • Decision: p < 0.05 → reject H₀ → heteroscedasticity ❌. p > 0.05 → homoscedastic ✅.
from statsmodels.stats.diagnostic import het_goldfeldquandt
stat, p_value, _ = het_goldfeldquandt(MLR_vif_model.resid, df_feature_vif)

10.4 Normality of Residuals Q-Q + Shapiro

qqplot(MLR_vif_model.resid, line='s')          # points on the line = normal

stat, p_value = shapiro(MLR_vif_model.resid)   # Shapiro-Wilk test
sns.histplot(MLR_vif_model.resid, kde=True)    # bell shape = normal
  • Q-Q plot: residual points lie on the 45° line → normal.
  • Shapiro-Wilk: H₀ = residuals are normal. p > 0.05 → normal ✅.

Jarque-Bera test alternative

Another normality test, based on the skewness and kurtosis of the residuals. (It also appears directly in model.summary().)

JB = (n/6) · [ S² + ¼(K − 3)² ]  → S = skewness, K = kurtosis
  • H₀: residuals are normally distributed (skewness ≈ 0, kurtosis ≈ 3).
  • H₁: residuals are not normally distributed.
  • Decision: p > 0.05 → normality satisfied ✅. p < 0.05 → not normal ❌.
11

Feature Selection (drop insignificant)

Keep only features that actually matter. A feature is insignificant if its p-value > 0.05.

p_values = MLR_vif_model.pvalues
p_values.sort_values(ascending=False)   # biggest p-value = most insignificant

Method — Backward Elimination (drop one-by-one):

  1. Find the feature with the highest p-value (> 0.05).
  2. Drop it, rebuild the model.
  3. Repeat until all remaining features have p < 0.05.

Order dropped in the notebook: B → CRIM → ZN → INDUS → NOX.

df_significant = df_feature_vif.drop(['B','CRIM','ZN','INDUS','NOX'], axis=1)
MLR_sig = sm.OLS(df_target, df_significant).fit()
Key observation: as weak features are dropped, R² drops slightly but Adjusted R² rises — the model gets simpler and better. (In one iteration Adj R² dipped, showing that feature was borderline useful.)
12

Interaction Effect

Interaction = the effect of one feature depends on another. We test it by adding their product as a new feature.

df_interaction = df_significant.copy()
df_interaction['RM_LSTAT'] = df_interaction['RM'] * df_interaction['LSTAT']

MLR_interaction = sm.OLS(df_target, df_interaction).fit()
  • New feature RM_LSTAT = RM × LSTAT.
  • Add it to the score card and check: did R² / Adj R² improve?
  • Interaction does not mean the variables are collinear.
Everyday example: salt + sugar + water → the taste depends on the combination, not each alone. Same idea for features.
13

Model Evaluation

R-squared

R² = Explained variation / Total variation = SSR / SST
MLR_sig.rsquared

% of variation in PRICE explained by the features. R² = 0.87 → 87% explained. Always increases when you add features (even useless ones).

Adjusted R-squared

Adj R² = 1 − [(1 − R²)(n − 1) / (n − k − 1)]
MLR_sig.rsquared_adj
# manual:
n = len(df_significant); k = len(df_significant.columns)
adj = 1 - (1 - r_sq)*(n-1)/(n-k-1)

Like R² but penalises useless features. Best metric to compare MLR models. n = rows, k = number of features.

Overall F-test

F = (SST−SSE)/k ÷ SSE/(n−k−1)
MLR_sig.fvalue      # F statistic
MLR_sig.f_pvalue    # p-value of the F-test
  • Tests whether the whole model is significant (is at least one feature useful?). Similar to ANOVA for regression.

Hypotheses:

  • H₀: β₁ = β₂ = … = βₖ = 0  (no feature helps — model useless).
  • H₁: at least one β ≠ 0  (at least one feature helps).

Decision rule: p < 0.05 → reject H₀ → model is significant ✅.   p > 0.05 → model not significant ❌.

Error metrics

MetricMeaningCode
MAEMean of |actual − predicted|. Easy to read.mean_absolute_error
MSEMean of squared errors. Punishes big errors.mean_squared_error
RMSE√MSE. Same unit as target.np.sqrt(mse)
Rule: higher R²/Adj R² = better; lower MAE/RMSE = better.

Exam-Ready Recipe (write this order)

Definition: Multiple Linear Regression predicts one numeric target using two or more predictors: y = b0 + b1x1 + … + bkxk.

Full workflow:

  1. Read data; check head, shape, info; drop ID columns.
  2. Treat outliers (boxplot + IQR).
  3. Handle missing values.
  4. Scale numeric features; add_constant().
  5. Before-model assumptions: target numeric + no multicollinearity (correlation + VIF, drop high-VIF feature).
  6. Encode categorical variables → N−1 dummies.
  7. Build model: sm.OLS(y, X).fit(); read summary.
  8. After-model assumptions: linearity (residual plot), no autocorrelation (Durbin-Watson ≈ 2), homoscedasticity (Breusch-Pagan), normal residuals (Q-Q + Shapiro-Wilk).
  9. Feature selection: drop features with p > 0.05 one-by-one (backward elimination).
  10. Try an interaction feature; keep if Adj R² improves.
  11. Evaluate: R², Adjusted R², F-test, RMSE/MAE.

Model QP — Full Solve

SMLR ESA · 3 Hrs · 100 marks. Section A = theory (50), Section B = pseudo/Python code (50).

Section A — Theory (5 × 10)

A1. Handling missing values (10)

  • Deletion — drop rows/columns. Use only when very few are missing. Simple, but loses data.
  • Mean/Median imputation — fill numeric gaps. Median if outliers present. Keeps rows, but reduces variance.
  • Mode imputation — fill categorical gaps with the most frequent value.
  • Forward/Backward fill — carry nearby value; good for time-series.
  • Model-based (KNN / regression) — predict the missing value. Most accurate, most costly.
Also mention: spot non-standard missing values like "NA", "?", "-" and convert them to real NaN first.

A2. Why feature scaling matters (10)

  • Features on different scales (Area in 1000s vs Bedrooms 1–5) make distance/gradient methods biased toward big-number features.
  • Standardization (StandardScaler): mean 0, std 1 → (x − μ)/σ.
  • Normalization (MinMaxScaler): squeeze to 0–1 → (x − min)/(max − min).
  • Needs scaling: KNN, SVM, Gradient Descent, PCA, Ridge/Lasso.
  • Doesn't need scaling: plain OLS, Decision Trees, Random Forest.

A3. Bias-Variance tradeoff (10)

  • Bias = error from too-simple model → underfitting (bad on train AND test).
  • Variance = error from too-complex model → overfitting (great on train, bad on test).
  • Tradeoff: lowering one raises the other; aim for the balance with lowest test error.
  • Achieve balance: cross-validation, regularization (Ridge/Lasso), pick right complexity, more data.

A4. Hyperparameters vs parameters + tuning (10)

  • Parameters = learned from data (e.g. regression coefficients b0, b1).
  • Hyperparameters = set by you before training (e.g. Ridge/Lasso α, K in KNN).
  • Plain Linear Regression: essentially no hyperparameter to tune (OLS solves directly). But Ridge/Lasso versions have α → yes, tuning applies there.
  • 3 tuning techniques: Grid Search, Random Search, Bayesian Optimization (bonus: k-fold CV to score each setting).

A5. Feature selection — FFS, BE, RFE (10)

MethodHow it worksNote
Forward (FFS)Start empty; add the best feature each step.Fast for few features; may miss combos.
Backward (BE)Start with all; drop the weakest (highest p) each step.Used in the notebook.
RFEFit model, rank features, remove the weakest, repeat.Uses model importance; needs an estimator.
