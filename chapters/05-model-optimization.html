Big Picture: Bias, Variance & the Goal

Sessions 3–4 built and trimmed a linear model. Optimization is Session 5's job: making the model as accurate as possible on data it has never seen. Three sub-goals from the slides:

Optimization stepPlain meaning
Prediction EvaluationHow well does the model actually predict? (RMSE, MAPE, R²)
Model ValidationTest on held-out data to check it isn't fooling us (cross-validation).
Fine TuningSqueeze out the best performance (regularization + hyperparameter tuning).

1.1 Two enemies: Bias and Variance

Bias = the model is too simple to catch the real pattern. A straight line can never bend to follow a curve, so it's always a bit wrong — but wrong consistently. High bias → underfitting.
Variance = the model is too flexible and memorises the training data (even the noise). It nails train data but its answer swings wildly on new data. High variance → overfitting.
Analogy — studying for an exam: High bias = you skimmed one summary page, so you get everything a little wrong. High variance = you memorised last year's paper word-for-word; perfect on that paper, lost on this year's new questions. We want the student who understood the concepts — good on both.

1.2 Underfit vs Good fit vs Overfit

UnderfittingGood fit (robust)Overfitting
Modeltoo simplejust righttoo complex
Biashighlowlow
Variancelowlowhigh
Train errorhighlowvery low
Test errorhighlowhigh
The tell-tale sign of overfitting: a big gap between train error and test error (great on train, poor on test). This gap is called generalization error. Everything in this session — CV, regularization, tuning — exists to shrink that gap.

This notebook predicts house PRICE from area characteristics (crime rate, rooms, tax rate, etc.), with some extra interaction variables added.

df_house.head()      # first 5 rows

df_house.dtypes      # data type of each column

# RecNo is just a row id — it predicts nothing

df_house.isnull().sum()
Result: every count is 0 → no missing values, nothing to fix.

3.4 Split into features (X) and target (y), then dummy-encode

df_target  = df_house['PRICE']                 # y = what we predict
df_feature = df_house.drop('PRICE', axis=1)     # X = everything else

# remember which columns are numeric — we scale only these later
numeric_cols = df_feature.select_dtypes(include=[np.number]).columns

# turn text/categorical columns into 0/1 columns
df_feature = pd.get_dummies(data=df_feature, drop_first=True, dtype=np.uint)
Why drop_first=True? If a column is "Yes/No", one 0/1 column already says everything (0 = No, 1 = Yes). Keeping both would be redundant and cause the dummy-variable trap. Drop one to be safe.

3.5 Train–Test split

X = df_feature
y = df_target

X_train, X_test, y_train, y_test = train_test_split(
        X, y, random_state=10, test_size=0.2)   # 80% train, 20% test
random_state=10 just fixes the "random" shuffle so you get the same split every run → reproducible results.

3.6 Scale the numeric features Z-score

scaler = StandardScaler()
X_train[numeric_cols] = scaler.fit_transform(X_train[numeric_cols])   # fit + transform on TRAIN
X_test[numeric_cols]  = scaler.transform(X_test[numeric_cols])        # only transform on TEST
Golden rule — fit only on train: the scaler learns the mean & standard deviation from train data only (fit_transform), then applies those same numbers to test (transform). If you fit on the test set too, test information leaks into training — that's cheating.
Why scale at all before regularization? Regularization punishes big coefficients. A feature measured in large numbers (e.g. TAX in thousands) would get an unfairly big penalty just because of its units. Scaling puts everyone on a level field so the penalty is fair.

Normalization vs Standardization exam wording

Two ways to scale. This notebook uses Standardization (StandardScaler). Follow the faculty wording below in the exam:

Normalization (Min-Max)Standardization (Z-score)
Formula(x − min) / (max − min)(x − mean) / σ
Outputfixed range 0 → 1mean 0, std 1 (no fixed range)
Use when…distribution is unknown / non-Gaussiandata is roughly Gaussian
Outliersget squashed by themkeeps their impact
Faculty line to write: use Normalization when the distribution is unknown or not Gaussian; use Standardization when the data is roughly Gaussian, and prefer it when important outliers should retain their impact — which is why this notebook picks StandardScaler.

Multiple Linear Regression (OLS)

OLS = Ordinary Least Squares: the plain linear regression that finds the line minimising the sum of squared errors. The notebook builds it twice — once in statsmodels, once in sklearn — only to compare them. We keep the sklearn one going forward.

4.1 statsmodels version (for the summary table)

# ** statsmodels ALWAYS needs a constant column added (for the intercept b0) **
stats_ols_model = sm.OLS(y_train, sm.add_constant(X_train)).fit()
stats_ols_model.summary()

# predict on test (also add_constant here)
test_pred_stats = stats_ols_model.predict(sm.add_constant(X_test))

4.2 The four error metrics

print("Test MSE  :", mean_squared_error(y_test, test_pred_stats))
print("Test RMSE :", np.sqrt(mean_squared_error(y_test, test_pred_stats)))
print("Test MAE  :", mean_absolute_error(y_test, test_pred_stats))
print("Test MAPE :", mean_absolute_percentage_error(y_test, test_pred_stats) * 100)

MSEAverage of squared errors. Punishes big misses hard.units are squared → hard to read

4.3 sklearn version (the one we keep)

linreg    = LinearRegression()
MLR_model = linreg.fit(X_train, y_train)     # NOTE: sklearn needs NO add_constant

print("R-Squared :", MLR_model.score(X_train, y_train))
MLR_model.coef_        # the slopes (one per feature)
MLR_model.intercept_   # the constant b0

One fact examiners love: add_constant() is for statsmodels OLS only. sklearn's LinearRegression adds the intercept automatically — never add it yourself there.
What is R²? The % of the target's variation the model explains. R² = 0.75 means "the model accounts for 75% of why prices differ." model.score() in sklearn returns R².

Helper Functions & the Score Card

We build many models, so we make small reusable functions and one table to compare them all. Learn these — they're reused in every later section.

5.1 RMSE and MAPE helpers

def get_train_rmse(model):
    train_pred = model.predict(X_train)
    return round(np.sqrt(mean_squared_error(y_train, train_pred)), 4)

def get_test_rmse(model):
    test_pred = model.predict(X_test)
    return round(np.sqrt(mean_squared_error(y_test, test_pred)), 4)

def get_test_mape(model):
    test_pred = model.predict(X_test)
    return mean_absolute_percentage_error(y_test, test_pred) * 100

5.2 R² and Adjusted R²

def get_score(model):
    r_sq = model.score(X_train, y_train)          # R²
    n = X_train.shape[0]                        # rows
    k = X_train.shape[1]                        # features
    r_sq_adj = 1 - ((1-r_sq)*(n-1)/(n-k-1))     # Adjusted R²
    return [r_sq, r_sq_adj]
Why Adjusted R²? Plain R² never goes down when you add features, even useless ones. Adjusted R² penalises extra features, so it only rises if a new feature genuinely helps. Fairer for comparing models of different sizes.

5.3 The score card (compare all models in one table)

score_card = pd.DataFrame(columns=['Model_Name', 'Alpha', 'l1-ratio', 'R-Squared',
                                   'Adj. R-Squared', 'Test_RMSE', 'Test_MAPE'])

def update_score_card(algorithm_name, model, alpha='-', l1_ratio='-'):
    new_row = {'Model_Name': algorithm_name,
               'Alpha': alpha, 'l1-ratio': l1_ratio,
               'Test_MAPE': get_test_mape(model),
               'Test_RMSE': get_test_rmse(model),
               'R-Squared': get_score(model)[0],
               'Adj. R-Squared': get_score(model)[1]}
    score_card.loc[len(score_card)] = new_row

5.4 Coefficient bar-plot helper

def plot_coefficients(model, algorithm_name):
    df_coeff = pd.DataFrame({'Variable': X.columns, 'Coefficient': model.coef_})
    sorted_coeff = df_coeff.sort_values('Coefficient', ascending=False)
    sns.barplot(x='Coefficient', y='Variable', data=sorted_coeff)

This lets us see regularization at work later — the bars (coefficients) shrink towards zero.

5.5 Record the baseline MLR model

train_rmse = get_train_rmse(MLR_model)
test_rmse  = get_test_rmse(MLR_model)
print('Train RMSE:', train_rmse, '| Test RMSE:', test_rmse)
print('Difference:', train_rmse - test_rmse)

update_score_card(algorithm_name='Linear Regression', model=MLR_model)
score_card
Interpretation: train and test RMSE are close → not badly overfit. If the gap were large, that would scream overfitting → and regularization (§8) would be the cure.

Cross-Validation (Model Validation)

A single train/test split can be lucky or unlucky — maybe the test rows happened to be easy. Cross-validation (CV) repeats the test on different slices and averages, giving a more trustworthy score.

Analogy: judging a restaurant by one dish is risky. Order five different dishes and average your rating — a much fairer verdict. Each dish takes a turn being "the one you judge on."

6.1 k-Fold Cross-Validation

Procedure: chop the data into k equal parts (folds). Each fold takes a turn as the test set while the other k−1 folds train. Do this k times, then average the k scores.

# cv = 5 → 5 folds, scoring = 'r2' → score each fold by R²
scores = cross_val_score(estimator=LinearRegression(),
                         X=X_train, y=y_train,
                         cv=5, scoring='r2')

print('All scores:', scores)
print('Min:', min(scores), 'Max:', max(scores), 'Avg:', np.mean(scores))
Read it like this: five R² numbers come back. If they're all close together, the model is stable. If they swing a lot, the model is fragile (high variance). The average is your honest performance estimate.

6.2 Leave-One-Out CV (LOOCV)

The extreme version of k-fold: k = number of rows. Each run tests on exactly one observation and trains on all the rest. For n rows → n runs.

loocv_rmse = []
loocv = LeaveOneOut()

for train_index, test_index in loocv.split(X_train):
    # one row is the test set, everything else trains
    X_tr, X_te = X_train.iloc[train_index], X_train.iloc[test_index]
    y_tr, y_te = y_train.iloc[train_index], y_train.iloc[test_index]

    linreg = LinearRegression().fit(X_tr, y_tr)
    rmse = np.sqrt(mean_squared_error(y_te, linreg.predict(X_te)))
    loocv_rmse.append(rmse)

print('Min:', min(loocv_rmse), 'Max:', max(loocv_rmse), 'Avg:', np.mean(loocv_rmse))
k-Fold (e.g. k=5)LOOCV
Runsk (few)n = one per row (many)
Speedfastslow on big data
Uses all data for training?almostmaximally (n−1 rows each time)
Downside—runs highly correlated → high-variance estimate
Rule of thumb: use k-fold (5 or 10) as the everyday default; reach for LOOCV only on small datasets where you can't spare any rows.

Gradient Descent & SGD

OLS solves for the best coefficients with one formula. Gradient descent instead walks to the answer step by step — essential when data is huge and the formula is too expensive.

7.1 The idea in one picture

Analogy — hiking down in fog: you're on a hill (the error) and want the lowest valley. You can't see the bottom, so you feel the slope under your feet and step downhill. Steep slope → big step; nearly flat → tiny step. Repeat until the ground is flat (slope ≈ 0). That flat spot is the minimum error.

  • Cost function = the error we want to shrink (for regression, the sum of squared residuals). Also called loss or error function.
  • Learning rate (α) = the step size. It's a hyperparameter (you set it, the model doesn't learn it).
  • The update rule: new parameter = old parameter − (learning rate × slope).
new β = old β − α · (derivative of cost)   →   repeat until slope ≈ 0
Getting α right matters: too big → you leap over the valley and never settle (or diverge). Too small → correct but painfully slow. You want steps that are large far away and shrink as you near the bottom.

7.2 Three flavours of gradient descent

TypeUses per stepAccuracySpeed
Batch GD (vanilla)all rowsHighSlow
Mini-Batch GDa small group of rowsModerateModerate
Stochastic GD (SGD)one rowLower / noisierFast
SGD analogy: instead of asking the whole class before every step (batch), you ask one random student (stochastic). Each answer is noisier, but you take far more steps far faster — great for big data, and you can keep adding new data as it arrives.

7.3 Build linear regression with SGD

sgd = SGDRegressor(random_state=0)
linreg_with_SGD = sgd.fit(X_train, y_train)

print('RMSE on train set:', get_train_rmse(linreg_with_SGD))
print('RMSE on test set:',  get_test_rmse(linreg_with_SGD))

7.4 Compare coefficients: OLS vs SGD

plt.subplot(1,2,1); plot_coefficients(MLR_model,       'Linear Regression (OLS)')
plt.subplot(1,2,2); plot_coefficients(linreg_with_SGD, 'Linear Regression (SGD)')
plt.tight_layout(); plt.show()

8

Regularization: Ridge, Lasso & Elastic Net

This is the main cure for overfitting. Plain OLS only minimises error, so it can grow huge coefficients to chase every wiggle in the train data. Regularization adds a penalty for big coefficients, forcing the model to stay simple.

cost = error (OLS)  +  λ · penalty(coefficients)
Analogy — a strict budget: OLS is a shopper with an unlimited card who buys every feature at full strength. Regularization puts them on a budget (λ): every coefficient now "costs" something, so the model only spends on features that truly earn their keep. This deliberately adds a little bias to buy a big drop in variance → less overfitting.
What is λ (alpha)? The strength of the penalty, a hyperparameter. λ = 0 → no penalty (plain OLS). Bigger λ → harder squeeze, coefficients shrink more. Too big → underfitting. The best λ is found by trying values (that's §9). In sklearn this knob is called alpha.
Occam's razor: "when two models fit equally well, prefer the simpler one." Regularization is exactly this principle turned into maths.

8.1 Ridge Regression L2

Penalty = λ × (sum of squared coefficients). Ridge shrinks coefficients towards zero but never exactly to zero — it keeps every feature, just quieter.

Ridge cost = Σ(yₐ − yₚ)²  +  λ · Σ(βⱼ)²
alpha_value = 1
ridge = Ridge(alpha=alpha_value, max_iter=500)
ridge.fit(X_train, y_train)
print('RMSE on test set:', get_test_rmse(ridge))

update_score_card(algorithm_name='Ridge Regression', model=ridge, alpha=alpha_value)
# try a stronger penalty and SEE the coefficients shrink
alpha_value = 25
ridge = Ridge(alpha=alpha_value, max_iter=500).fit(X_train, y_train)

plt.subplot(1,2,1); plot_coefficients(MLR_model, 'Linear Regression (OLS)')
plt.subplot(1,2,2); plot_coefficients(ridge,     'Ridge Regression')
plt.tight_layout(); plt.show()
Interpretation: the Ridge bars are visibly shorter than OLS — coefficients squeezed towards 0, but all still present.

8.2 Lasso Regression L1

Penalty = λ × (sum of |coefficients|). The key difference: Lasso can push weak coefficients exactly to zero — so it drops features entirely. That makes Lasso a built-in feature selector.

Lasso cost = Σ(yₐ − yₚ)²  +  λ · Σ|βⱼ|
alpha_value = 0.5
lasso = Lasso(alpha=alpha_value, max_iter=500).fit(X_train, y_train)
print('RMSE on test set:', get_test_rmse(lasso))

# which variables did Lasso switch OFF (coefficient == 0)?
df_lasso = pd.DataFrame({'Variable': X.columns, 'Coefficient': lasso.coef_})
df_lasso.Variable[df_lasso.Coefficient == 0].to_list()

update_score_card(algorithm_name='Lasso Regression', model=lasso, alpha=alpha_value)
Interpretation: in the coefficient plot, several Lasso bars sit at exactly zero → those features are eliminated. Fewer features = simpler, more explainable model.

8.3 Ridge vs Lasso — the one-line difference

Ridge (L2)Lasso (L1)
PenaltyΣ(β²)Σ|β|
Shrinks coefficients?YesYes
Sets some to exactly 0?No — keeps allYes — drops features
Use when…all/most features matter, many interactionsmany features are useless and should go

8.4 Elastic Net L1 + L2

Can't decide between Ridge and Lasso? Elastic Net uses both penalties. The l1_ratio mixes them:

l1_ratio = 0 → pure Ridge  |  l1_ratio = 1 → pure Lasso  |  0 < l1_ratio < 1 → a blend
alpha_value    = 0.1
l1_ratio_value = 0.01

enet = ElasticNet(alpha=alpha_value, l1_ratio=l1_ratio_value, max_iter=500)
enet.fit(X_train, y_train)
print('RMSE on test set:', get_test_rmse(enet))

update_score_card(algorithm_name='Elastic Net Regression', model=enet,
                  alpha=alpha_value, l1_ratio=l1_ratio_value)
When to use which (exam favourite): Ridge if it's important to keep all predictors. Lasso if some predictors are junk you want gone. Elastic Net when there are so many variables you can't tell — it hedges by doing a bit of both.
9

Hyperparameter Tuning

So far we guessed alpha (0.5, 1, 25…). Tuning automates the search for the best value. Reminder: a hyperparameter is a knob you set (alpha, l1_ratio, learning rate), unlike coefficients which the model learns from data.

9.1 GridSearchCV — try every combination

You hand it a grid of values; it tests all of them with cross-validation and returns the winner. Thorough, but slow if the grid is big.

Analogy: trying every key on a keyring, one by one, until the door opens. Guaranteed to find it — but could take a while.
# ----- Ridge -----
tuned_parameters = [{'alpha': [1e-3, 1e-2, 0.1, 1, 10, 20]}]

ridge_grid = GridSearchCV(estimator=Ridge(),
                          param_grid=tuned_parameters,
                          cv=3)                 # 3-fold CV for each alpha
ridge_grid.fit(X_train, y_train)

print('Best parameters:', ridge_grid.best_params_)
print('RMSE on test set:', get_test_rmse(ridge_grid))

update_score_card(algorithm_name='Ridge (GridSearchCV)', model=ridge_grid,
                  alpha=ridge_grid.best_params_.get('alpha'))
# ----- Lasso: same idea, different grid -----
tuned_parameters = [{'alpha': [0.1, 0.2, 0.5, 0.8, 1, 5, 10]}]
lasso_grid = GridSearchCV(estimator=Lasso(), param_grid=tuned_parameters, cv=3)
lasso_grid.fit(X_train, y_train)
print('Best parameters:', lasso_grid.best_params_)
# ----- Elastic Net: TWO knobs → grid is alpha × l1_ratio -----
tuned_parameters = [{'alpha':    [0.01, 0.05, 0.1, 0.3, 0.5, 0.7, 1, 10, 20],
                     'l1_ratio': [0.0001, 0.001, 0.01, 0.1, 0.2, 0.5, 0.7]}]
enet_grid = GridSearchCV(estimator=ElasticNet(), param_grid=tuned_parameters, cv=3)
enet_grid.fit(X_train, y_train)
print('Best parameters:', enet_grid.best_params_)
Key attributes: after fitting, .best_params_ gives the winning values and .best_estimator_ is the model already built with them. Grid size grows fast: 9 alphas × 7 l1_ratios = 63 combinations × 3 folds = 189 fits.

9.2 RandomizedSearchCV — try a random sample

Instead of all combinations, it tries n_iter random ones. Much faster; may miss the exact best but usually lands very close.

Analogy: rather than every key on the ring, you try a handful of likely-looking keys. Far quicker, and one of them usually works.
tuned_parameters = [{'alpha': [1e-10, 1e-8, 1e-4, 1e-3, 1e-2, 0.1, 1, 5, 10, 20, 40, 60, 80, 100]}]

ridge_rand = RandomizedSearchCV(estimator=Ridge(),
                                param_distributions=tuned_parameters,
                                cv=3, n_iter=10,      # test only 10 random alphas
                                random_state=0, n_jobs=-1)  # n_jobs=-1 → use all CPU cores
ridge_rand.fit(X_train, y_train)
print('Best parameters:', ridge_rand.best_params_)

Lasso and Elastic Net follow the identical pattern — swap in Lasso() / ElasticNet() and their grids. The one new argument vs GridSearch is n_iter (how many random tries) and the key is param_distributions instead of param_grid.

ArgumentMeaning
estimatorthe model to tune (Ridge, Lasso…)
param_distributionsdict of hyperparameters + values to sample from
cvnumber of CV folds (default 5)
n_iterhow many random combinations to try (default 10)
n_jobs=-1run in parallel using every CPU core
GridSearchCV — exhaustive, tries everything. Most thorough, most expensive. Use with small grids.
RandomizedSearchCV — samples randomly. Faster, may miss the exact best. Use with big search spaces.

9.3 Bayesian Optimization (Optuna)

The smartest of the three. Grid and Random search have no memory — each try ignores the last. Bayesian search learns from past trials and steers the next guess toward promising regions, so it finds a good value in fewer tries.

Analogy — "hotter / colder": Grid checks every square of the room blindly. Bayesian plays hot-and-cold: each guess uses the feedback from the last to move closer to the hidden object. We use Optuna (beginner-friendly: search space + objective live in one function).
# !pip install optuna
import optuna
from optuna.samplers import TPESampler   # only needed to fix a seed for repeatability

# 1) objective: build the model for a suggested alpha, return the score to MINIMISE
def objective(trial):
    params = {'alpha': trial.suggest_float('alpha', 0.0001, 10)}
    ridge = Ridge(**params).fit(X_train, y_train)
    return get_test_rmse(ridge)          # lower RMSE = better

# 2) minimise RMSE over 100 smart trials
study = optuna.create_study(direction='minimize', sampler=TPESampler(seed=10))
study.optimize(objective, n_trials=100)

print('Best RMSE:', study.best_trial.value)
print('Best Params:', study.best_trial.params)

# 3) build the final model with the best alpha found
ridge_optuna = Ridge(**study.best_trial.params).fit(X_train, y_train)
update_score_card(algorithm_name='Ridge (Optuna)', model=ridge_optuna,
                  alpha=ridge_optuna.alpha)

Lasso and Elastic Net use the same three steps — only the model inside objective changes. For Elastic Net the objective suggests two values:

def objective(trial):
    params = {'alpha':    trial.suggest_float('alpha', 0.001, 10),
              'l1_ratio': trial.suggest_float('l1_ratio', 0.01, 0.99)}
    enet = ElasticNet(**params).fit(X_train, y_train)
    return get_test_rmse(enet)

9.4 Pick the winner

# sort every model by Test RMSE and highlight the lowest
score_card = score_card.sort_values('Test_RMSE').reset_index(drop=True)
score_card.style.highlight_min(color='lightblue', subset='Test_RMSE')
The payoff: the whole session funnels into this one table. The model with the lowest Test RMSE (and a small train–test gap) is your best, most trustworthy model.
★

Exam-Ready Recipe (write in this order)

Goal of the session: reduce generalization error (the train–test gap) by balancing bias and variance.

  1. Prep: load data, drop id column (RecNo), check missing values, split X/y, get_dummies(drop_first=True).
  2. Split & scale: train_test_split(random_state=…); StandardScaler — fit_transform on train, transform on test.
  3. Baseline OLS: sklearn LinearRegression (no add_constant). Record RMSE, MAPE, R², Adj R².
  4. Validate: cross_val_score(cv=5) for a stable score; LOOCV on small data.
  5. Gradient descent: SGDRegressor — fast on big data; coefficients come out smaller.
  6. Regularize (cures overfitting by shrinking coefficients):
    • Ridge (L2) Σβ² — shrinks all, drops none.
    • Lasso (L1) Σ|β| — sets weak ones to 0 → feature selection.
    • Elastic Net — both; l1_ratio mixes (0 = Ridge, 1 = Lasso).
  7. Tune the hyperparameter (alpha): GridSearchCV (all combos) → RandomizedSearchCV (random subset, n_iter) → Optuna (Bayesian, learns from past trials).
  8. Decide: sort the score card by Test RMSE; lowest RMSE with a small train–test gap wins.
Three facts examiners love: (1) add_constant() is for statsmodels only. (2) Scale before regularizing, or the penalty is unfair. (3) Regularization adds bias to cut variance — that trade is the whole point.
